YAPISI:

    SQL KOMUTLARI

END

Buradaki bölümler:

ÖR:

CREATE OR ALTER PROCEDURE SP_Kullanicilar_Ekle

    @KullaniciAdi NVARCHAR(50),
    @Sifre NVARCHAR(50),
    @Ad NVARCHAR(50),
    @Soyad NVARCHAR(50),
    @Telefon NVARCHAR(13),
    @Mail NVARCHAR(100),
    @RolId INT,
    @AktiflikDurumu BIT,
    @ProfilResim NVARCHAR(200)

AS
BEGIN

    INSERT INTO Kullanicilar
    (
        kullanici_adi,
        sifre,
        ad,
        soyad,
        telefon,
        mail,
        rol_id,
        aktiflik_durumu,
        olusturulma_tarihi,
        profil_resim
    )
    VALUES
    (
        @KullaniciAdi,
        @Sifre,
        @Ad,
        @Soyad,
        @Telefon,
        @Mail,
        @RolId,
        @AktiflikDurumu,
        GETDATE(),
        @ProfilResim
    );

END
GO

Kullanicilar.cs sınıfındaki Ekle() metodu prosedürü çağırır:

public void Ekle()
{
    using (SqlConnection sqlConnection = Baglanti())
    {
        SqlCommand sqlCommand =
            new SqlCommand(
                "SP_Kullanicilar_Ekle",
                sqlConnection
            );

        sqlCommand.CommandType =
            CommandType.StoredProcedure;

        sqlCommand.Parameters.AddWithValue(
            "@KullaniciAdi",
            KullaniciAdi
        );

        sqlCommand.Parameters.AddWithValue(
            "@Sifre",
            Sifre
        );

        sqlCommand.Parameters.AddWithValue(
            "@Ad",
            Ad
        );

        sqlCommand.Parameters.AddWithValue(
            "@Soyad",
            Soyad
        );

        sqlCommand.Parameters.AddWithValue(
            "@Telefon",
            Telefon
        );

        sqlCommand.Parameters.AddWithValue(
            "@Mail",
            Mail
        );

        sqlCommand.Parameters.AddWithValue(
            "@RolId",
            RolId
        );

        sqlCommand.Parameters.AddWithValue(
            "@AktiflikDurumu",
            AktiflikDurumu
        );

        sqlCommand.Parameters.AddWithValue(
            "@ProfilResim",
            ProfilResim
        );

        sqlCommand.ExecuteNonQuery();
    }
}

DETAYLAR:

- sqlCommand.CommandType = CommandType.StoredProcedure;

Bu satır, yazdığımız ifadenin normal SQL sorgusu değil, Stored Procedure adı olduğunu belirtir.

- sqlCommand.Parameters.AddWithValue("@Mail", Mail);

C# içindeki Mail değerini prosedürdeki:

@Mail

parametresine gönderir.

Parametre isimleri birebir uyumlu olmalıdır.

DOSYA İŞLEMLERİ CLASS'I:

using System;
using System.Collections.Generic;
using System.Linq;
using System.Web;
using System.IO;

namespace ModbusProjesi.AppCode
{
    public class DosyaIslemleri
    {
        public string ResimKaydet(HttpPostedFile dosya)
        {
            string uzanti = Path.GetExtension(dosya.FileName).ToLower();

            string yeniDosyaAdi = System.Guid.NewGuid().ToString() + uzanti;

            string yol = HttpContext.Current.Server.MapPath("~/Files/") + yeniDosyaAdi;

            dosya.SaveAs(yol);

            return yeniDosyaAdi;
        }

        public void ResimSil(string dosyaAdi)
        {
            if (string.IsNullOrEmpty(dosyaAdi))
                return;

            string yol = HttpContext.Current.Server.MapPath("~/Files/") + dosyaAdi;

            if (File.Exists(yol))
            {
                File.Delete(yol);
            }
        }
    }
}

2.İşlem sınıflarından try-catch-finally kaldırılması

Önceden KullaniciIslemleri içerisindeki metotlarda buna benzer bir mantık vardı:

public bool Ekle(Kullanicilar kullanicilar)
{
    try
    {
        // SQL işlemleri...
        return true;
    }
    catch (Exception)
    {
        // hata yönetimi
        return false;
    }
    finally
    {
        veritabaniIslemleri.Bitir();
    }
}

Bunu kaldırdık.

Yeni KullaniciIslemleri daha sade:

public bool Ekle(Kullanicilar kullanicilar)
{
    veritabaniIslemleri.ProsedurSec(Kullanicilar.C_Sp_Ekle);

    // Parametreler...

    return veritabaniIslemleri.Calistir();
}

Bunun çok önemli bir nedeni vardı:

KullaniciIslemleri içerisindeki bir metot kendi kendine:

veritabaniIslemleri.Bitir();

veya transaction üzerinde işlem yaparsa, üst tarafta devam edecek diğer işlemler aynı bağlantı ve transaction'ı kullanamaz hale geliyordu.

Bizim kullanıcı ekleme akışımız mesela tek metottan oluşmuyor:

btnKaydet_Click
      ↓
Transaction başlat
      ↓
KayitVarMi()
      ↓
Ekle()
      ↓
ID alınır
      ↓
Kullanıcı adı oluşturulur
      ↓
KullanıcıAdiGuncelle()
      ↓
COMMIT
      ↓
Bitir()

Dolayısıyla KayitVarMi() kendi içinde bağlantıyı kapatırsa:

KayitVarMi()
     ↓
Bitir() ❌
     ↓
Ekle()
     ↓
Bağlantı yok!

ve bizim karşılaştığımız şu tarz hatalar ortaya çıkıyordu:

Fill: SelectCommand.Connection özelliği başlatılmamış.

Aynı şekilde transaction'ın yanlış yerde Rollback/Dispose edilmesi:

SqlTransaction tamamlandı; artık kullanılabilir değil.

hatasına yol açabiliyordu.

Yeni sorumluluk dağılımımız

Şimdi mantık şu:

KullaniciIslemleri
→ Sadece kullanıcı işlemini yapar.

VeritabaniIslemleri
→ Connection / Command / Transaction altyapısını yönetir.

Page (btnKaydet_Click)
→ İşlem akışını yönetir.
→ try-catch-finally burada bulunur.

Örneğin:

try
{
    veritabaniIslemleri.Baslat(
        VeritabaniIslemleri.IslemTip.BAGIMLI);

    // KayitVarMi
    // Ekle
    // KullaniciAdiGuncelle

    veritabaniIslemleri.Uygula();
}
catch (Exception ex)
{
    veritabaniIslemleri.GeriAl();

    lblMesaj.Text = ex.Message;
}
finally
{
    veritabaniIslemleri.Bitir();
}

6. BAGIMLI – BAGIMSIZ işlem tipi

Bu tamamen yeni ve önemli.

public enum IslemTip
{
    BAGIMLI,
    BAGIMSIZ
}

BAĞIMSIZ:
Tek başına çalışan işlem.

Örneğin:
veritabaniIslemleri.Baslat(VeritabaniIslemleri.IslemTip.BAGIMSIZ);

Listeleme, giriş, tek kayıt getirme gibi işlemlerde kullanılabilir.

BAĞIMLI:
Birden fazla SQL işleminin hep birlikte başarılı olması gereken durum.

Örneğin:
veritabaniIslemleri.Baslat(VeritabaniIslemleri.IslemTip.BAGIMLI);

8. DataRow, SatirGetir() ve DegerGetir() 

Dosyada DataTable ve ExecuteScalar() var ama bizim oluşturduğumuz abstraction yok.

DataRow satir = veritabaniIslemleri.SatirGetir();

Tek kullanıcı için.

DataTable tablo = veritabaniIslemleri.TabloGetir();

MAX ID ile Kullanıcı Adı Oluşturma

Projede kullanıcı adı artık kullanıcı tarafından girilmez. Kullanıcı eklendikten sonra oluşan ID değeri kullanılarak sistem tarafından otomatik oluşturulur.

Format:

Modbus + Yıl + 4 Haneli ID

ID = 1  → Modbus20260001
ID = 25 → Modbus20260025

Son eklenen kullanıcının ID'sini almak için:

CREATE PROCEDURE SP_Kullanicilar_MAXIDGETIR
AS
BEGIN
    SELECT ISNULL(MAX(id), 0)
    FROM Kullanicilar;
END

C# tarafında:

public int MaxIdGetir()
{
    veritabaniIslemleri.ProsedurSec(Kullanicilar.C_Sp_MaxIdGetir);

    object sonuc = veritabaniIslemleri.DegerGetir();

    return Convert.ToInt32(sonuc);
}

Kullanıcı eklendikten sonra ID alınır ve kullanıcı adı oluşturulur:

int yeniId = kullaniciIslemleri.MaxIdGetir();

kullanicilar.Id = yeniId;

kullanicilar.KullaniciAdi ="Modbus" + DateTime.Now.Year + yeniId.ToString("D4");

ToString("D4"), ID'yi 4 haneli yapar:

1  → 0001
25 → 0025

İlk kayıt sırasında ID henüz belli olmadığı ve kullanici_adi alanı boş bırakılamadığı için geçici olarak benzersiz bir Guid kullanılır:

kullanicilar.KullaniciAdi = Guid.NewGuid().ToString();

ID oluştuktan sonra bu geçici değer Modbus20260001 şeklindeki gerçek kullanıcı adıyla değiştirilir.

Genel akış:

Geçici GUID
    ↓
Kullanıcı Ekle
    ↓
MaxIdGetir
    ↓
ID = 1
    ↓
Modbus20260001
    ↓
Kullanıcı Adını Güncelle

Not: MAX(id) yöntemi local ve tek kullanıcılı mevcut proje için kullanılmıştır. Çok kullanıcılı sistemlerde SCOPE_IDENTITY() veya OUTPUT daha güvenlidir.
